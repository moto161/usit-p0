<h2>1. NOTE-1｜锁所有权与 Lock Token 契约</h2>

<h3>1.1 LockToken 数据结构（拒绝布尔标志）</h3>

<pre><code>
@dataclass(frozen=True)
class LockToken:
    authorization_id: str        # 归属授权
    process_id: int              # 获取进程 PID
    thread_id: int               # 获取线程标识
    lock_path: str               # 锁文件绝对路径（必须与 authorization_id 对应）
    lock_file_identity: str      # 锁文件对象身份（inode/dev 或 Windows 等价）
    acquisition_id: str          # 每次获取唯一（UUID/ULID）
    acquired_at: str             # 获取时间戳
    platform: str                # &quot;windows-ntfs&quot; / &quot;posix-local&quot;
    lock_proto_version: str      # 锁协议版本
    released: bool               # 生命周期状态（仅进程内可变，token 其余字段不可变）
</code></pre>

<p><strong>禁止</strong>：token 只含 <code>locked=True</code> 布尔标志。必须能据此独立校验&quot;谁、在哪个进程/线程、锁了哪个文件对象、何时、是否仍有效&quot;。</p>

<h3>1.2 所有权校验规则</h3>

<tr><td>规则</td><td>约束</td></tr>
<tr><td>跨线程使用</td><td><strong>默认禁止</strong>（token 绑定 thread_id，跨线程校验失败）</td></tr>
<tr><td>跨进程传递</td><td><strong>默认禁止</strong>（token 绑定 process_id + lock_file_identity）</td></tr>
<tr><td>锁文件路径</td><td>必须与 authorization_id 对应（<code>_lock_path(auth_id)</code> 唯一映射）</td></tr>
<tr><td>锁文件身份</td><td>必须与实际持有锁的文件对象一致（inode/dev 或等价）</td></tr>
<tr><td>已释放 token</td><td>拒绝（<code>released == True</code> → 校验失败）</td></tr>
<tr><td>过期/失效/伪造 token</td><td>拒绝（acquisition_id 不可伪造，锁文件身份不匹配即拒）</td></tr>
<tr><td>跨授权复用</td><td>不同 authorization_id <strong>不得复用</strong>同一 token</td></tr>
<tr><td>重复释放</td><td>幂等拒绝第二次（<code>released</code> 已 True，二次 release 报错或忽略并记录）</td></tr>
<tr><td>错误释放</td><td>非当前 token 持有者释放 → 拒绝并记录异常</td></tr>
<tr><td>持锁期间替换锁文件</td><td>锁文件身份变化 → 锁失效 → 后续 <code>assert_lock_owned</code> 全部 DENY</td></tr>

<h3>1.3 函数调用契约（前置/后置/所有权变化/异常）</h3>

<tr><td>函数</td><td>前置条件</td><td>后置条件</td><td>锁所有权变化</td><td>异常处理</td></tr>
<tr><td><code>acquire_authorization_lock(auth_id)</code></td><td>锁文件可打开</td><td>返回 LockToken（released=False）</td><td>获得所有权</td><td>失败返回 None → 上层 DENY</td></tr>
<tr><td><code>release_authorization_lock(token)</code></td><td>token 有效且未释放</td><td>token.released=True</td><td>释放所有权</td><td>重复释放/错误释放 → 记录并拒绝</td></tr>
<tr><td><code>assert_lock_owned(auth_id, token)</code></td><td>token 由调用者持有</td><td>通过则返回，不改变状态</td><td>不变</td><td>不匹配 → DENY_LOCK_NOT_OWNED</td></tr>
<tr><td><code>atomic_commit(...)</code></td><td>无（自行取锁）</td><td>事务提交结果</td><td>获取→释放（finally）</td><td>异常仍释放锁</td></tr>
<tr><td><code>atomic_commit_locked(...)</code></td><td>已持 auth_id 锁（token 传入）</td><td>锁内事务结果</td><td>不变（不取锁）</td><td>异常上抛，锁由外层释放</td></tr>
<tr><td><code>handoff_execution(...)</code></td><td>无（自行取锁）</td><td>交接结果</td><td>获取→释放</td><td>finally 释放</td></tr>
<tr><td><code>revoke_authorization(auth_id)</code></td><td>无（自行取锁）</td><td>撤销结果</td><td>获取→释放</td><td>finally 释放</td></tr>

<p><strong>核心</strong>：<code>atomic_commit_locked</code> 与 <code>handoff_execution</code> 之间通过 <code>assert_lock_owned</code> 校验真实所有权；任何 <code>_locked</code> 后缀函数都不自行取锁。</p>

<h3>1.4 跨平台规则（不声称等价）</h3>

<tr><td>项</td><td>Windows/NTFS</td><td>POSIX 本地</td></tr>
<tr><td>锁原语</td><td><code>msvcrt.locking</code>（字节范围锁）</td><td><code>flock</code>（fd 级）</td></tr>
<tr><td>句柄生命周期</td><td>handle 关闭即释放</td><td>fd 关闭即释放</td></tr>
<tr><td>进程异常退出</td><td>OS 释放 handle → 锁释放</td><td>OS 关闭 fd → 锁释放</td></tr>
<tr><td>线程内重复获取</td><td>需谨慎（同进程多 handle）</td><td>需谨慎（同进程多 fd）</td></tr>
<tr><td>文件替换/删除/重创建</td><td>锁绑定原 handle，替换后新 handle 无锁 → 失效</td><td>删除后 inode 变 → 锁失效</td></tr>
<tr><td>网络文件系统（SMB/UNC/NFS）</td><td><strong>不保证</strong></td><td><strong>不保证</strong></td></tr>

<p><strong>结论</strong>：Windows 与 POSIX 锁行为<strong>不完全等价</strong>，本设计不宣称等价。无法证明的平台能力标记 <code>NOT_VERIFIED</code>。网络文件系统一律 DENY 或降级 <code>LOCK_UNVERIFIED</code>。</p>

<h3>1.5 验收</h3>

<ul><li>任意持锁函数都能通过 <code>assert_lock_owned</code> 验证<strong>真实锁所有权</strong>。</li></ul>
<ul><li>伪造 token、跨线程 token、跨授权 token、已释放 token 均<strong>不能通过</strong>校验。</li></ul>
<ul><li>全链路<strong>无隐含重复加锁路径</strong>。</li></ul>

<h2>2. NOTE-2｜事务 Journal/Pending 清理与保留策略</h2>

<h3>2.1 事务文件分类</h3>

<tr><td>类型</td><td>路径模式</td><td>内容</td></tr>
<tr><td>PREPARED journal</td><td><code>journal/&lt;txn_id&gt;.txn</code>（state=PREPARED）</td><td>事务意图，未确认提交</td></tr>
<tr><td>COMMITTED journal</td><td>同上（state=COMMITTED）</td><td>已确认提交</td></tr>
<tr><td>ABORTED journal</td><td>同上（state=ABORTED）</td><td>已回滚</td></tr>
<tr><td>INDETERMINATE journal</td><td>同上（state=INDETERMINATE）</td><td>崩溃，状态未知</td></tr>
<tr><td>candidate document</td><td><code>pending/&lt;txn_id&gt;.json</code></td><td>完整新文档候选</td></tr>
<tr><td>temporary document</td><td><code>pending/&lt;txn_id&gt;.json.tmp</code></td><td>写入中的临时文件</td></tr>
<tr><td>recovery metadata</td><td>随 journal 字段（pending_path / pending_sha256 / expected_revision / new_revision）</td><td>恢复判定依据</td></tr>

<h3>2.2 清理准入规则</h3>

<tr><td>状态</td><td>允许清理？</td><td>说明</td></tr>
<tr><td>COMMITTED</td><td>✅（满足保留期）</td><td>终态，可清理（审计保留后）</td></tr>
<tr><td>ABORTED</td><td>✅（无副作用）</td><td>终态，可清理</td></tr>
<tr><td>PREPARED</td><td>❌</td><td>未终结，禁止自动清理</td></tr>
<tr><td>INDETERMINATE</td><td>❌</td><td>状态未知，禁止自动清理</td></tr>
<tr><td>正在恢复中</td><td>❌</td><td>恢复流程持有引用，禁止清理</td></tr>

<p><strong>规则</strong>：</p>
<ul><li>无法证明事务已安全终结时<strong>不得清理</strong>；无法判断时 <strong>DENY</strong>。</li></ul>
<ul><li>清理操作<strong>必须持有授权级锁</strong>（避免与恢复/新事务竞争）。</li></ul>
<ul><li>清理失败<strong>不影响授权继续执行</strong>（清理是旁路，非主路径）。</li></ul>
<ul><li>清理过程再崩溃 → 下次恢复时按 journal 状态重判，幂等。</li></ul>
<ul><li>journal 与候选文档保留期限：审计保留期内不删；终态且过保留期才可清理。</li></ul>

<h3>2.3 幂等与审计字段</h3>

<pre><code>
@dataclass(frozen=True)
class CleanupRecord:
    cleanup_id: str              # 全局唯一
    transaction_id: str          # 被清理事务
    candidate_digest: str        # 候选文件摘要（校验用）
    cleanup_result: str          # CLEANED / FAILED / SKIPPED
    cleanup_timestamp: str
    cleanup_actor: str           # 执行者标识
    cleanup_failure_reason: str | None
</code></pre>

<ul><li>清理幂等：重复 cleanup 同一 transaction_id，结果一致，不重复删除。</li></ul>
<ul><li><strong>不得删除仍被恢复流程引用的候选文件</strong>（清理前检查 journal 状态与引用）。</li></ul>

<h3>2.4 清理状态机</h3>

<pre><code>
PENDING → CLAIMED → CLEANED
   │          │
   └──────────┴→ FAILED（可重试，仍 PENDING）
                 → INDETERMINATE（崩溃，下次恢复重判）
</code></pre>

<tr><td>转换</td><td>触发</td><td>说明</td></tr>
<tr><td>PENDING → CLAIMED</td><td>取得锁 + 判定可清理</td><td>标记本进程负责清理</td></tr>
<tr><td>CLAIMED → CLEANED</td><td>删除 journal+候选成功</td><td>记录 cleanup_id/result</td></tr>
<tr><td>CLAIMED → FAILED</td><td>删除失败</td><td>保留 journal，记录失败原因，可重试</td></tr>
<tr><td>CLAIMED → INDETERMINATE</td><td>清理中崩溃</td><td>下次恢复按 journal 状态重判</td></tr>

<h3>2.5 验收</h3>

<ul><li>每种事务状态都有明确保留/清理策略。</li></ul>
<ul><li>未终结（PREPARED/INDETERMINATE）或恢复中的事务<strong>不会被误删</strong>。</li></ul>
<ul><li>清理失败<strong>不会被误报成功</strong>。</li></ul>
